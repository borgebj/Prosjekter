Modelloversikt

Dette mini-prosjektet bruker en enkel struktur for et nevralt nettverk: tre input-funksjoner, et skjult lag og én outputnode som forutsier om input ser ut som spam.

Output er ligger på rekken <0.0, 1.0>, hvor 0.0 indikerer 0% sannsynlighet for spam, og 1.0 indikerer 100% sannsynlighet for spam.

Hva det viser

  • Egendefinert implementasjon av nevralt nettverk
  • Aktiveringsfunksjoner og tapfunksjoner
  • Treningsløkke og prediksjonsflyt
  • Logikk for lagring og lasting av modell

Hvordan data representeres

Modellen bruker et lite syntetisk datasett bygget rundt tre enkle trekk (features):

  • free -- hvor mange ganger ordet “free” vises
  • win -- hvor mange ganger ordet “win” vises
  • offer-- hvor mange ganger ordet “offer” vises

Ta f.eks. en kort e-post som:

“Congratulations! You have won a free offer today. Claim your prize now!”

Før modellen ser den, forenkles teksten til et antall mistenkelige ord:

  • free = 1
  • win = 1
  • offer = 1

Dette konverteres deretter til en funksjonsvektor: [1, 1, 1].

Det nevrale nettverket prosesserer dette inputet og gir en sannsynlighet, for eksempel rundt 85–90 % sannsynlighet for spam for en melding med flere mistenkelige signaler.

Interessante kodesnutter

Dette prosjektet er spesielt godt for å demonstrere hvordan et nevralt nettverk faktisk fungerer, uten å skjule alt bak et rammeverk med ferdilaget og forenklede funksjoner. Her er tre sentrale deler av koden som viser den tekniske kjernen.

1. Forward pass og backpropagation

Dette er selve læringsmekanismen: først beregner nettverket en prediksjon, så går det bakover gjennom lagene for å finne feilen, og oppdaterer vektene. Koden viser hvordan hver neuron får en forutsetning (Z), en aktivering (A) og til slutt en feildifferensial som brukes til å justere vektene.

def forward(self, X):
    pre_activations = []
    activations = [X]

    for i in range(len(self.weights)):
        Z = activations[-1] @ self.weights[i] + self.biases[i]
        pre_activations.append(Z)

        if i == len(self.weights) - 1:
            A = self.output_activation.func(Z)
        else:
            A = self.hidden_activation.func(Z)

        activations.append(A)

    return pre_activations, activations


def backward(self, y_true, pre_acts, acts):
    N = y_true.shape[0]
    dA = self.loss_function.derivative(y_true, acts[-1])

    for i in reversed(range(len(self.weights))):
        if i == len(self.weights) - 1:
            dZ = dA * self.output_activation.derivative(pre_acts[i])
        else:
            dZ = dA * self.hidden_activation.derivative(pre_acts[i])

        dW = acts[i].T @ dZ / N
        dB = np.sum(dZ, axis=0) / N

        self.weights[i] -= self.lr * dW
        self.biases[i] -= self.lr * dB
        dA = dZ @ self.weights[i].T

Her ser vi at modellen faktisk er skrevet for å være generell, ikke bare “spam-klassifiserer”. Ved å pakke aktiveringsfunksjonen og tapfunksjonen inn i små containere kan samme nettverk bytte mellom ReLU, sigmoid, softmax og binary cross-entropy uten å måtte skrive helt ny kode hver gang.

3. ReLU, sigmoid og binary cross-entropy i utility.py

Dette er den lille, men veldig viktige funksjonsbiblioteket som gjør modellen operasjonell. ReLU brukes i det skjulte laget for å introdusere ikke-linearitet, sigmoid brukes i output-laget for sannsynlighetsberegning, og binary cross-entropy måler hvor langt prediksjonen er fra den riktige klassen.

def relu(x):
    return np.maximum(0, x)


def sigmoid(x):
    return 1 / (1 + np.exp(-x))


def binary_cross_entropy(y_true, y_pred):
    y_pred += 1e-15
    return -np.mean(y_true * np.log(y_pred) + (1 - y_true) * np.log(1 - y_pred))
